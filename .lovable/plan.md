# BACY-10 Gmail-by-voice: audit and plan

## Audit (checked in this repo and workspace)

1. How Gmail was read in chat vs. an app
   - Chat: a one-off call through the workspace connection "Bacany's Gmail" (OAuth, gateway-backed). It is NOT linked to this project, so the app has no Gmail access today.
   - Deployed app: the connection must be linked to this project. That injects `GOOGLE_MAIL_API_KEY` (plus existing `LOVABLE_API_KEY`) into this web app's server runtime only, called via `https://connector-gateway.lovable.dev/google_mail/gmail/v1/...`.
2. Can app runtime use the connector? Yes, from a TanStack server function or server route in this web app. Not from the APK, and not directly from the LiveKit Python agent: the agent (`agent/src/agent.py`, generated by `tools/bacy10_build_livekit_package.py` + `tools/bacy10_phone_memory_upgrade.py`) runs on LiveKit Cloud and never receives Lovable secrets. Lovable chat MCP tools are not callable by the agent at all.
3. Separate Google OAuth mandatory? No, for the owner's own mailbox (the linked connection is the owner's account). Only needed if other users should read their own Gmail (App User Connector).
4. Current state: the agent has `BrowserTools` and `PhoneTools` only; no Gmail or connector tool exists. Token Worker (`infra/livekit-token-bridge.js`) only mints LiveKit tokens; untouched.

## Minimum implementation

1. Link "Bacany's Gmail" to this project; confirm the `gmail.readonly` scope via connection config.
2. Add a secret `BACY10_AGENT_KEY` (user sets it in Lovable Secrets and the same value in LiveKit agent secrets).
3. `src/lib/gmail.server.ts`: list latest N (1-10) inbox messages with `format=metadata`, Subject/From/Date only, one batch request; surface gateway status/body on errors.
4. `src/routes/api/public/bacy/gmail-subjects.ts`: POST, constant-time check of `Authorization: Bearer BACY10_AGENT_KEY`, returns `{subjects:[...]}`; 401 otherwise. Read-only.
5. `src/routes/api/public/bacy/connectors.ts`: same auth; returns which connectors are linked (presence of env keys only, never values), for "what can you access?".
6. `tools/bacy10_phone_memory_upgrade.py` (or new `tools/bacy10_gmail_tools.py` hooked in the builder): writes `agent/src/gmail_tools.py` with `@function_tool` `list_latest_email_subjects(count)` and `list_connectors()` calling the endpoints above using env `BACY10_APP_URL` + `BACY10_AGENT_KEY`; registers next to `PhoneTools` in `agent.py`; prompt line: read subjects only, never claim mail actions.
7. `.github/workflows/bacy10-livekit-complete-source.yml`: assert `gmail_tools.py` exists and is registered; add `BACY10_APP_URL`/`BACY10_AGENT_KEY` placeholders to the agent `.env.example` template only.
8. Test: vitest for the auth check and subject parsing; then a live call to the endpoint returns the three latest subjects.

## Preserved
Package ID `za.co.bacy10.personalassistant`, agent name `bacy-10`, LiveKit token endpoint, pairing flow, all existing secrets. No Gmail claim inside the APK until the redeployed agent is voice-tested.
